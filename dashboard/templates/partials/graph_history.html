{# A run's graph-merge history, rendered inside job_status.html. Two modes, keyed on whether the job is still running: - running: subscribes to /jobs/{id}/graph-events (api/sse.py) and receives each streamed byte exactly once. `call-open` prepends a card into the list; that card's own elements then subscribe to their delta events. This replaced a 1s poll that re-rendered every call's entire accumulated content on every tick, so the response grew for the duration of the run. - finished: a plain static render of job.graph_history, with no subscriptions to leak. This is also what a page load of an already-finished job serves. A fresh connection replays from the first call, so reloading the page mid-run rebuilds the whole history rather than showing only what happens next. `sse-close="stream-close"` tears the connection down on the server's final frame, so a finished card doesn't hold an EventSource open. The container is emitted for the whole life of a running job (before merging starts, it is simply empty) — see the note in job_status.html on why it must never be swapped in later. The :has() rule in static/src/input.css keeps it hidden until the first card lands. The toggle button below is pure client state (toggleMergeHistory in static/js/app.js) — it only flips a `hidden` class on .graph-history-list, so it never interferes with the SSE swap target that list is (or, for a finished job, the static cards already inside it). Expanded by default while running (the thing you'd actually want to watch), collapsed by default once finished (past runs default out of the way, one click to inspect). #}
