{# A run's graph-merge history, rendered inside the collapsible .log-detail panel of job_status.html's compact log row. Two modes, keyed on whether the job is still running: - running: subscribes to /jobs/{id}/graph-events (api/sse.py) and receives each streamed byte exactly once. `call-open` prepends a card into the list; that card's own elements then subscribe to their delta events. This replaced a 1s poll that re-rendered every call's entire accumulated content on every tick, so the response grew for the duration of the run. - finished: a plain static render of job.graph_history, with no subscriptions to leak. This is also what a page load of an already-finished job serves. A fresh connection replays from the first call, so reloading the page mid-run rebuilds the whole history rather than showing only what happens next. `sse-close="stream-close"` tears the connection down on the server's final frame, so a finished card doesn't hold an EventSource open. This partial owns no expand/collapse control of its own — job_status.html's chevron toggles the whole .log-detail panel (meta line + this) as one unit, now that a run is a single compact log row rather than a multi-section card. The container itself is still emitted for the whole life of a running job (before merging starts, it is simply empty) so the SSE subscription below exists before the first call arrives; see the note in job_status.html on why this element must never be swapped in later. The :has() rule in static/src/input.css keeps it from leaving a blank gap in an expanded detail panel until the first call lands. #}
{# Whitespace control (the -%}/{%- pairs below) matters here, not just style: the :has(> .graph-history-list:empty) rule needs this div to have *zero* child nodes while a run is pending/scraping/cleaning/extracting (job.is_finished false, no calls yet) — a stray whitespace text node between the tags is enough to make :empty stop matching and leave an empty gap visible before the first call exists. #}
